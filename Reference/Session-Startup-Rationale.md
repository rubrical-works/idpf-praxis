Injected context is not reloaded after compaction, and that loss is accepted: each row carries its own remedy, and the note only explains it at the moment it is shown. A check that timed out or failed to run gets the block-mechanics note.
## Branch Sync Offer (#2635, #2687, #2668, #3014)
**Why the hook offers rather than acts.** It follows the `06-runtime-triggers.md` *offer, don't force* convention: the hook never mutates the working tree; it instructs Claude to ask.
**Why conflicting paths, not dirtiness, decide the offer.** `branch-sync-check.js` intersects `git status --porcelain` against `git diff --name-only HEAD..@{upstream}` and returns the overlap as `conflictingPaths`. A dirty tree whose modified files are absent from the incoming diff fast-forwards cleanly, so it still gets the offer. Blocking on dirtiness alone would refuse a safe update in the common case. With conflicting paths a fast-forward would abort, and stashing or discarding on the user's behalf would destroy work.
**Why the check fetches first.** A branch goes stale for the same reason its remote-tracking ref does — measuring against the cached ref is silent precisely when the offer is needed. The fetch is best-effort: it carries its own timeout and `GIT_TERMINAL_PROMPT=0`, and any failure sets `fetched: false` and falls back to the cached ref.
**Why `fetched: false` is reported at every stale-able status (#2687).** `up-to-date` is the one status which otherwise emits nothing, so a stale all-clear is indistinguishable from a verified one. Observed on `idpf/0.99.0` (2026-08-29) — an expired `gh` token against an HTTPS remote with no `credential.helper`, a branch 3 commits behind for an entire session, and no `Branch Sync:` row at any point.
**Why `no-upstream` is excluded.** `fetchUpstream()` returns `false` whenever no remote or mergeRef is configured, so that status *always* carries `fetched: false`. Emitting the cached-ref caveat there would attach a staleness warning to an upstream that does not exist — reporting a configuration state as a fetch failure. The envelope `message` carries the same qualification, while `success` and `status` are unchanged: consumers key off `status`, so this is wording, not contract.
**Why `diverged` offers navigation, never a strategy (#2668).** A prior implementation (#2001) offered a rebase/merge/skip choice; that prompt commits the user to a history rewrite before they have seen the divergence, so #2518 removed it and reported only. #2668 restored an offer of a **different kind**: the hook names *where* the divergence gets resolved and still names no git command. This answers #2518's two recorded objections rather than overriding them. **Sequencing/consent:** naming a recovery path is not a history rewrite, so nothing commits the user at the moment they know least about what diverged. **Non-assertability:** the text is a *fixed string*, assertable per-state exactly like every other branch-sync state. "Reports only" described the #2518 state and is now false; a reader acting on it would drop the recovery path, which is the whole of what #2668 added. The full record: `Construction/Design-Decisions/2026-08-31-diverged-startup-navigation-offer.md` (dev repository).
**Why #3014 added evidence, not a strategy.** `branch-sync-check.js` derives the analysis (fork point, each side's commits with issue refs and board status, overlapping paths, dirty paths the remote also changes, last pull) and the hook renders it as a fixed-shape block — still assertable per field, still no git command, still nothing run. `/sync-branch` is named first because it is the recovery that needs no issue in review — the gap the `/done` pointer left when the local commits belonged to closed issues.
## Peers Row (#2661)
The row introduces no ownership probe, halting gate, or path-scope enforcement; those belong to the Station proposal (#2640). `none` emits no row because a lone session is the common case, and a line every startup announcing it is noise. The pre-move root `.overwatch.json` was read as a fallback for one release after #2957 moved the marker. Under quiet narration a receipt reply is recorded with no narration; otherwise with at most one line. An absent `entrypoint` is never read as `sdk-cli`, and `SendMessage` addresses by `ListAgents` name, which is why a headless session is registered but not tool-reachable. Peers are discovered only in this exact working directory, on this machine, for this user. The rest of the peer-messaging reasoning is in `Reference/Cross-Session-Messaging.md`.
