## Command-shape corrections (#2997)
Corrections for specific command shapes — heredocs with backticks, unsafe `$(...)`, inline `--body`, backslash and absolute temp-file paths, quoting, inline JSON, `--flag value`, loops over command output, CMD-style variables, `rm -rf` with several paths, and PowerShell process management — live in `.claude/metadata/shell-pattern-corrections.json`, injected by the hook only when a command matches, rather than resident in every session. `date /t` and `taskkill /F` are always wrong on Git Bash, so the hook blocks them.
## Parallel tool failures
When Claude Code runs multiple tools in parallel and one fails, all siblings are aborted with "Sibling tool call errored", which is not the real error. Destructive and cleanup commands (`rm`, `git clean`) and network calls therefore never run in parallel with state-changing operations like `TaskUpdate`.
## Temp-file names (#1034, #2980, #2983, #2985)
Concurrent sessions in one working directory are a supported, announced setup — peer discovery and the startup `Peers:` row exist for it — so two sessions running the same command share any fixed path. One session's write landing between another's write and its `gh pmu` call sends the wrong body to the wrong issue, and one session's `rm` can remove a file the other has not read yet. For editing, the issue number is the natural discriminator: two sessions editing *different* issues cannot collide, and two editing the *same* issue are a conflict the name should not hide. For creation no number exists until after the body is written. A suffix composed rather than generated is not random — two sessions reasoning the same way reach the same "random" name. A command holding two files at once (`/create-backlog`'s epic and story bodies, `/plan-workstreams`' mapping and plan) collides with itself on one shared name, no second session required.
## Junctions and discovery (#2736)
An earlier version of rule 05 said tools other than Glob "access them fine" without qualification. That was true of explicit reads and false of discovery, and it is the sentence that made the defect look impossible: because `.claude/rules/` was deployed as a junction, none of the 8 auto-loaded rules reached Claude's context in any Praxis Hub Manager-deployed project. Nothing errored, the files read fine through the link, and the startup block still rendered. The full account is in `Reference/Deployment-Awareness-Detail.md` § Rules Must Be Copied, Not Symlinked (dev repository). The copied-versus-symlinked split is measured, not assumed — `Reference/Deployment-Awareness.md` → *Dependency Resolution for Copied Skills*.
